# GLM-5.3 线：VestigeKV 与 DSA 的二合一设计

工程线文档，不进论文。所有数值均为 2026-09-23 在 2×RTX PRO 6000（TP=2）上对
GLM-5.3-Flash-NVFP4 的实测；代码在 sglang fork 的 `glm53-index-sigma` 分支。

## 1. 两个公式，同一个结构

DSA 每层每步：

```
k_idx,i = W_k · h_i                          训练出的投影，128 维，fp8 存储
l_i     = Σ_h w_h · (W_q,h · h_t) · k_idx,i   学出的代理分数
S       = top-2048 by l_i                    固定预算
o       = MLA(q_t, S)                        精确注意力
```

VestigeKV 每层每步：

```
c_i  = content_i · Vᵀ                                  拟合出的投影，r=64 维
s_i  = (c_i · q_sk)·sc + zp·sc/√(d−r) · ρ_i · ‖q_res‖   投影分数 + 保形证书
S    = kept ∪ { i : s_i > max1 }                        阈值，门槛为保留集最高分
o    = MLA(q_t, S)                                      精确注意力
```

两者都是 **低秩投影打分 → 按规则选集合 → 对集合精确注意力**。差别只有两处：

| | DSA | VestigeKV |
|---|---|---|
| 投影来源 | `W_k` 与模型一起训练，是真实分数的代理 | `V` 对查询分布做 PCA，是真实分数 `content·q` 的直接投影 |
| 能否出证书 | 不能，代理与真实分数无解析关系 | 能，投影外的部分由 `ρ_i·‖q_res‖` 兜住 |
| 选集合规则 | 固定 top-k | 阈值 |

统一形式：

```
score_i = P(token_i) · P'(q_t)
S       = rule(score)          rule ∈ { top-k, 阈值+证书 }
o       = MLA(q_t, S)
```

## 2. 哪个投影更好——实测

对同一个 oracle（用当步真实解码查询对全部行稠密打分取 top-2048）：

| 投影 | 覆盖 oracle 的比例 |
|---|---|
| DSA 的 `W_k`（128 维，训练） | 0.440（真实文本）/ 0.374（合成） |
| VestigeKV 的 `V`（64 维，拟合，attend 2048） | 0.738 / 0.679 |

VestigeKV 的投影明显更好，因为它投影的是真实分数本身。端到端 RULER（n=10，65 格）：
VestigeKV 0.958 对 DSA 0.942，8 胜 4 负，约 1.9 个标准误，方向一致但边际。

## 3. 数学第一性：为什么是这个结构

问"解码能否复用上一步的工作"，即问 `N(q_t) = Σ exp(q_t·k_i) v_i` 能否由 `N(q_{t−1})` 得到：

```
N(q_t) = Σ_i exp(q_{t−1}·k_i) · exp(Δ·k_i) · v_i ,   Δ = q_t − q_{t−1}
```

`exp(Δ·k_i)` 带下标 i，提不出求和号。**softmax 的分子不是任何固定状态在查询变化下的线性泛函**，
所以历史输出在代数上不可缓存，不是工程限制。

三条绕法：

- **泰勒展开**：内层要存矩 `Σ w_i k_i^{⊗m} v_i`，m=1 即 512³，维数爆炸。这正是线性注意力必须整个丢掉 softmax 的原因。
- **换核** `φ(q)·φ(k)`：状态可增量更新，但那是另一种注意力。GLM 已在 KDA 层用它；剩下的全注意力层正是不能这么走的层。
- **只近似选择、不近似输出**：选择的分数 `s_i = q·k_i` 对 q **线性**，`s_i(q_t) = s_i(q_{t−1}) + Δ·k_i` 精确成立。仍要碰每个 k——除非 Δ 落在少数方向上，那就把键预先投影到该子空间，每步只做小点积，子空间外用范数界兜住。

**第三条推出来的就是 `csk = content·Vᵀ` 加 `cc·ρ·q_res`。** 草图不是工程技巧，是"查询移动时如何廉价更新分数"的数学解；
`V` 拟合到标定查询上，就是"Δ 落在少数方向"这个前提的实现。现有设计是数学给出的形态。

推演留下的唯一杠杆在 **界** 上：`q_res` 是查询落在基之外的部分，它决定证书的膨胀量，进而决定火率、取回和围栏。
实测：让基包含当前查询（乐观上界），`q_res` 降 23%，界的膨胀从约 9 倍分数标准差降到 7 倍。

## 4. 今天差距在哪——逐内核拆解

同一条臂，4k 对 32k，标记锚定的解码窗口内每步 GPU 时间：

| 内核 | 4k | 32k | 增长 | 归属 |
|---|---|---|---|---|
| `_prologue_scores` | 19.65 | 57.50 | **+37.85** | VestigeKV，保留集稠密打分 |
| `kpool_topk_transform` | 70.32 | 90.12 | +19.80 | DSA |
| `sm120_fp8_paged_mqa_logits` | 32.75 | 39.89 | +7.14 | DSA |
| `_scan_batched`（档案扫描） | 36.06 | 37.21 | **+1.15** | VestigeKV |
| `_vk_dsa_decode_split` | 75.64 | 74.98 | −0.66 | VestigeKV（fork 自 DSA） |
| `_ring_write` | 15.08 | 15.03 | −0.05 | VestigeKV，**已删除** |

两条结论：

- **档案扫描在 32k 以下是平的。** 池化、降秩、fp8 三条路都在压它的字节，斜率收益分别 ≤2.9%，与此吻合。
- **增长在保留集打分**（`ρ·S` 行的稠密打分）。用草图替代它对三个用途全部失败：真 argmax 有 15% 不在草图 top-64 内、熵的相对误差以千计、门控判定在合成语料上等于抛硬币。它是承重的。

fp8 在完整 4k–116k 区间、且标定证书正常服务时，实测降斜率 **9.6%**（0.233 → 0.211 ms/10 万 token；
DSA 同口径 0.113，即对 DSA 从 2.07× 到 1.87×），收益只在 32k 以上出现，116k 处每步快 0.027 ms（步长 11.6 ms）。
两个早先的数字都是假象：2.9% 是 KV 池把流截断在 78k；22% 是两臂都跑在异步标定构建静默失败的树上
（c88b3ae37e..3e77f58cfe，worker 里一个未定义名字，临时 zp=8 证书把整个档案点火），
fp8 减半的是一个被放大了的扫描——fp16 臂的斜率只变了 3%，fp8 臂变了 18%，正是"按行字节的改动在被放大的行数上测量"的特征。

## 5. 二合一设计

```
主路径:  VestigeKV 投影打分 + 阈值 + 证书 → S
围栏:    若 |S| > 2048 → 改用 DSA 的 top-2048
```

这就是现有围栏规则，放进统一框架后成本结构变得清楚：

```
VestigeKV 链（常驻）       137 µs   前言 57.50 + 扫描 37.21 + 归并 30.67 + 簿记 11.39
DSA 链（围栏步才需要）     166 µs   logits 39.89 + top-k 90.12 + hadamard 10.46 + act_quant 25.75
```

围栏步比例为零时 137 < 166，快过 DSA；为一时 303，即今天的状态。
**整个差距就是 DSA 的 indexer 跑了多少不必要的步。**

而"多少步"由一个结构性事实决定：围栏**逐层**判定，精简图**整步**切换——任一层溢出，整步 11 层的 indexer 全跑。
逐层围栏率实测 0.24；精简图实测只在 20–23% 的步触发。**DSA 的 indexer 在近八成的步上全量运行，其中大部分层并未溢出。**

## 6. 优化计划

按收益/风险排序。

### 6.1 静态逐层切分（零派发成本）

用 VKSTATS 的 `ovf_by_layer` 历史，把几乎从不溢出的层固定为"永不跑 DSA"，老溢出的层固定为"总跑"。
派发烘进 CUDA graph，成本为零。每免掉一层约 15 µs（166/11）。

动态逐层派发实测 +0.68 ms/step，比 DSA 整条链还贵，**封死**。

主路径换成 VestigeKV 的投影（覆盖 0.738 对 0.440）后，各层溢出率应下降，能进免跑桶的层更多。
这是二合一相对单纯围栏的额外收益。

### 6.2 基追踪查询（压 `q_res`）

更频繁重拟合 V，或在线自适应。不改结构，与所有否定结果不冲突。乐观上界 23%，真实收益需线上量。
仪表：`SGLANG_DEBUG_VESTIGEKV_RECALL_AUDIT`，直接量基不追踪的后果——实际达成的召回。

### 6.3 fp8 草图存储（已落地，默认关闭）

长程斜率 −9.6%（见 §4），质量中性（围栏率 0.2597 对 0.2410，中位步取回为零，needle 通过）。
在 in-graph 生产路径上验证通过。对 210 µs 的差距贡献约 0.03 ms/步（116k），与簿记融合同量级；翻默认值前建议再跑一次 RULER。

### 6.4 簿记内核融合（收益小）

VestigeKV 6 个簿记内核共 11.39 µs，融成 2 个约省 5–7 µs。对 210 µs 的差距约 3%。低风险，低收益。

### 6.5 ρ（唯一能动斜率的旋钮，暂不动）

`ρ·S` 是唯一增长项的系数。降 ρ 直接降斜率，代价是保留更少、火率上升。需要先有 6.2 把界压紧，再评估。

## 7. 已封死的路（附实测）

| 路线 | 实测 | 原因 |
|---|---|---|
| 4:1 池化档案 | 可靠界触发 99.6% 的组，真正含触发行的只有 1.8% | 组内偏差 ≈ 均值，界空。DSA 能池化因为它取固定 top-k；证书认证阈值，不能 |
| 降秩到 16 | 等召回下总流量 +26%；线上围栏率 0.515 对 0.237 | 火率暴涨抵消扫描节省 |
| σ 驱动跳层 | 相邻层保留集重合 0.296（真实文本） | σ 是逐层信号，不跨层 |
| pivot 化 top-k | 带宽 128 命中 68%，值 0.35% | 切点不可预测 |
| 剪索引（路线 C） | tier 1 单独在 RULER 上只留 19% 的 oracle | tier 2 承担大部分召回 |
| 补充 Δ（路线 A） | 增量对 Δ 线性无集中，Δ=128 只 +0.4 点 | 新增行均匀散布在 σ 排序中 |
| 用草图给保留集打分 | max/熵/门控三项全败 | 门槛需真 max |
| 跨 DSA 边界融合内核 | — | logits 三个后端全是 C++，无 Triton |

## 8. 方法论教训

- **字节率不等于时间率。** 三次把"每 token 132 字节"当成"主导斜率"，没验证内核耗时是否随字节变化。
- **测量区间会制造假结论。** 78k 截断把 22% 误判成 2.9%；32k 以下的"平"被外推到全程。
- **火率是成本，召回率是质量。** 低秩火率更低是因为漏得多；必须在固定召回下比。
- **`_assert_async` 在下一个同步点报错**，traceback 指向无关调用。
- **KV 池是权重之后的残值**，对 `mem-fraction-static` 超线性敏感（0.95→78k，0.955→118k）；长流前先探池子。
