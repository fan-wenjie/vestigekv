# GLM-5.3 线：VestigeKV 与 DSA 的二合一设计

工程线文档，不进论文。所有数值均为 2026-09-23 在 2×RTX PRO 6000（TP=2）上对
GLM-5.3-Flash-NVFP4 的实测；代码在 sglang fork 的 `glm53-index-sigma` 分支。

## 1. 两个公式，同一个结构

DSA 每层每步：

```
k_idx,i = W_k · h_i                          训练出的投影，128 维，fp8 存储
l_i     = Σ_h w_h · (W_q,h · h_t) · k_idx,i   学出的代理分数
S       = top-2048 by l_i                    固定预算
o       = MLA(q_t, S)                        精确注意力
```

VestigeKV 每层每步：

```
c_i  = content_i · Vᵀ                                  拟合出的投影，r=64 维
s_i  = (c_i · q_sk)·sc + zp·sc/√(d−r) · ρ_i · ‖q_res‖   投影分数 + 保形证书
S    = kept ∪ { i : s_i > max1 }                        阈值，门槛为保留集最高分
o    = MLA(q_t, S)                                      精确注意力
```

两者都是 **低秩投影打分 → 按规则选集合 → 对集合精确注意力**。差别只有两处：

| | DSA | VestigeKV |
|---|---|---|
| 投影来源 | `W_k` 与模型一起训练，是真实分数的代理 | `V` 对查询分布做 PCA，是真实分数 `content·q` 的直接投影 |
| 能否出证书 | 不能，代理与真实分数无解析关系 | 能，投影外的部分由 `ρ_i·‖q_res‖` 兜住 |
| 选集合规则 | 固定 top-k | 阈值 |

统一形式：

```
score_i = P(token_i) · P'(q_t)
S       = rule(score)          rule ∈ { top-k, 阈值+证书 }
o       = MLA(q_t, S)
```

## 2. 哪个投影更好——实测

对同一个 oracle（用当步真实解码查询对全部行稠密打分取 top-2048）：

| 投影 | 覆盖 oracle 的比例 |
|---|---|
| DSA 的 `W_k`（128 维，训练） | 0.440（真实文本）/ 0.374（合成） |
| VestigeKV 的 `V`（64 维，拟合，attend 2048） | 0.738 / 0.679 |

VestigeKV 的投影明显更好，因为它投影的是真实分数本身。端到端 RULER（n=10，65 格）：
VestigeKV 0.958 对 DSA 0.942，8 胜 4 负，约 1.9 个标准误，方向一致但边际。

## 3. 数学第一性：为什么是这个结构

问"解码能否复用上一步的工作"，即问 `N(q_t) = Σ exp(q_t·k_i) v_i` 能否由 `N(q_{t−1})` 得到：

```
N(q_t) = Σ_i exp(q_{t−1}·k_i) · exp(Δ·k_i) · v_i ,   Δ = q_t − q_{t−1}
```

`exp(Δ·k_i)` 带下标 i，提不出求和号。**softmax 的分子不是任何固定状态在查询变化下的线性泛函**，
所以历史输出在代数上不可缓存，不是工程限制。

三条绕法：

- **泰勒展开**：内层要存矩 `Σ w_i k_i^{⊗m} v_i`，m=1 即 512³，维数爆炸。这正是线性注意力必须整个丢掉 softmax 的原因。
- **换核** `φ(q)·φ(k)`：状态可增量更新，但那是另一种注意力。GLM 已在 KDA 层用它；剩下的全注意力层正是不能这么走的层。
- **只近似选择、不近似输出**：选择的分数 `s_i = q·k_i` 对 q **线性**，`s_i(q_t) = s_i(q_{t−1}) + Δ·k_i` 精确成立。仍要碰每个 k——除非 Δ 落在少数方向上，那就把键预先投影到该子空间，每步只做小点积，子空间外用范数界兜住。

**第三条推出来的就是 `csk = content·Vᵀ` 加 `cc·ρ·q_res`。** 草图不是工程技巧，是"查询移动时如何廉价更新分数"的数学解；
`V` 拟合到标定查询上，就是"Δ 落在少数方向"这个前提的实现。现有设计是数学给出的形态。

推演留下的唯一杠杆在 **界** 上：`q_res` 是查询落在基之外的部分，它决定证书的膨胀量，进而决定火率、取回和围栏。
实测：让基包含当前查询（乐观上界），`q_res` 降 23%，界的膨胀从约 9 倍分数标准差降到 7 倍。

## 4. 今天差距在哪——逐内核拆解

同一条臂，4k 对 32k，标记锚定的解码窗口内每步 GPU 时间：

| 内核 | 4k | 32k | 增长 | 归属 |
|---|---|---|---|---|
| `_prologue_scores` | 19.65 | 57.50 | **+37.85** | VestigeKV，保留集稠密打分 |
| `kpool_topk_transform` | 70.32 | 90.12 | +19.80 | DSA |
| `sm120_fp8_paged_mqa_logits` | 32.75 | 39.89 | +7.14 | DSA |
| `_scan_batched`（档案扫描） | 36.06 | 37.21 | **+1.15** | VestigeKV |
| `_vk_dsa_decode_split` | 75.64 | 74.98 | −0.66 | VestigeKV（fork 自 DSA） |
| `_ring_write` | 15.08 | 15.03 | −0.05 | VestigeKV，**已删除** |

两条结论：

- **档案扫描在 32k 以下是平的。** 池化、降秩、fp8 三条路都在压它的字节，斜率收益分别 ≤2.9%，与此吻合。
- **增长在保留集打分**（`ρ·S` 行的稠密打分）。用草图替代它对三个用途全部失败：真 argmax 有 15% 不在草图 top-64 内、熵的相对误差以千计、门控判定在合成语料上等于抛硬币。它是承重的。

fp8 在完整 4k–116k 区间、且标定证书正常服务时，实测降斜率 **9.6%**（0.233 → 0.211 ms/10 万 token；
DSA 同口径 0.113，即对 DSA 从 2.07× 到 1.87×），收益只在 32k 以上出现，116k 处每步快 0.027 ms（步长 11.6 ms）。
两个早先的数字都是假象：2.9% 是 KV 池把流截断在 78k；22% 是两臂都跑在异步标定构建静默失败的树上
（c88b3ae37e..3e77f58cfe，worker 里一个未定义名字，临时 zp=8 证书把整个档案点火），
fp8 减半的是一个被放大了的扫描——fp16 臂的斜率只变了 3%，fp8 臂变了 18%，正是"按行字节的改动在被放大的行数上测量"的特征。

## 5. 二合一设计

```
主路径:  VestigeKV 投影打分 + 阈值 + 证书 → S
围栏:    若 |S| > 2048 → 改用 DSA 的 top-2048
```

这就是现有围栏规则，放进统一框架后成本结构变得清楚：

```
VestigeKV 链（常驻）       137 µs   前言 57.50 + 扫描 37.21 + 归并 30.67 + 簿记 11.39
DSA 链（围栏步才需要）     166 µs   logits 39.89 + top-k 90.12 + hadamard 10.46 + act_quant 25.75
```

围栏步比例为零时 137 < 166，快过 DSA；为一时 303，即今天的状态。
**整个差距就是 DSA 的 indexer 跑了多少不必要的步。**

而"多少步"由一个结构性事实决定：围栏**逐层**判定，精简图**整步**切换——任一层溢出，整步 11 层的 indexer 全跑。
逐层围栏率实测 0.24；精简图实测只在 20–23% 的步触发。**DSA 的 indexer 在近八成的步上全量运行，其中大部分层并未溢出。**

## 6. 优化计划

按收益/风险排序。

### 6.1 静态逐层切分（零派发成本）

用 VKSTATS 的 `ovf_by_layer` 历史，把几乎从不溢出的层固定为"永不跑 DSA"，老溢出的层固定为"总跑"。
派发烘进 CUDA graph，成本为零。每免掉一层约 15 µs（166/11）。

动态逐层派发实测 +0.68 ms/step，比 DSA 整条链还贵，**封死**。

主路径换成 VestigeKV 的投影（覆盖 0.738 对 0.440）后，各层溢出率应下降，能进免跑桶的层更多。
这是二合一相对单纯围栏的额外收益。

### 6.2 基追踪查询（压 `q_res`）

更频繁重拟合 V，或在线自适应。不改结构，与所有否定结果不冲突。乐观上界 23%，真实收益需线上量。
仪表：`SGLANG_DEBUG_VESTIGEKV_RECALL_AUDIT`，直接量基不追踪的后果——实际达成的召回。

### 6.3 fp8 草图存储（已落地，默认关闭）

长程斜率 −9.6%（见 §4），质量中性（围栏率 0.2597 对 0.2410，中位步取回为零，needle 通过）。
在 in-graph 生产路径上验证通过。对 210 µs 的差距贡献约 0.03 ms/步（116k），与簿记融合同量级；翻默认值前建议再跑一次 RULER。

### 6.4 簿记内核融合（收益小）

VestigeKV 6 个簿记内核共 11.39 µs，融成 2 个约省 5–7 µs。对 210 µs 的差距约 3%。低风险，低收益。

### 6.5 ρ（唯一能动斜率的旋钮，暂不动）

`ρ·S` 是唯一增长项的系数。降 ρ 直接降斜率，代价是保留更少、火率上升。需要先有 6.2 把界压紧，再评估。

## 7. 已封死的路（附实测）

| 路线 | 实测 | 原因 |
|---|---|---|
| 4:1 池化档案 | 可靠界触发 99.6% 的组，真正含触发行的只有 1.8% | 组内偏差 ≈ 均值，界空。DSA 能池化因为它取固定 top-k；证书认证阈值，不能 |
| 降秩到 16 | 等召回下总流量 +26%；线上围栏率 0.515 对 0.237 | 火率暴涨抵消扫描节省 |
| σ 驱动跳层 | 相邻层保留集重合 0.296（真实文本） | σ 是逐层信号，不跨层 |
| pivot 化 top-k | 带宽 128 命中 68%，值 0.35% | 切点不可预测 |
| 剪索引（路线 C） | tier 1 单独在 RULER 上只留 19% 的 oracle | tier 2 承担大部分召回 |
| 补充 Δ（路线 A） | 增量对 Δ 线性无集中，Δ=128 只 +0.4 点 | 新增行均匀散布在 σ 排序中 |
| 用草图给保留集打分 | max/熵/门控三项全败 | 门槛需真 max |
| 跨 DSA 边界融合内核 | — | logits 三个后端全是 C++，无 Triton |

## 8. 方法论教训

- **字节率不等于时间率。** 三次把"每 token 132 字节"当成"主导斜率"，没验证内核耗时是否随字节变化。
- **测量区间会制造假结论。** 78k 截断把 22% 误判成 2.9%；32k 以下的"平"被外推到全程。
- **火率是成本，召回率是质量。** 低秩火率更低是因为漏得多；必须在固定召回下比。
- **`_assert_async` 在下一个同步点报错**，traceback 指向无关调用。
- **KV 池是权重之后的残值**，对 `mem-fraction-static` 超线性敏感（0.95→78k，0.955→118k）；长流前先探池子。
- **异步构建吞异常，坏了没有任何服务侧信号。** 一个未定义名字让标定构建静默失败五次运行，临时 zp=8 证书一直在服务；每个数字之前先 `grep "async calibrated build failed"`。

## 11. 报告口径（2026-09-24 定）

预填充是算力密集、解码是带宽瓶颈，两者 SLO 不同，合并成一个数既看不出改动落在哪一侧，
也没法让读者换算到自己的设备。所以固定按五部分报，**不允许只报其中一半**：

| | 内容 | 防的是 |
|---|---|---|
| 1a | TTFT vs 提示长度（曲线） | 单点外推 |
| 1b | **语义属预填充、但延迟执行的工作**：VestigeKV 在前 ~76 个解码步里为提示词建索引（第 1 步临时 tier、~64 步标定阶梯、第 8 步后首次图捕获），实测 `build=121.8ms x44` | 从解码裁掉却不记到任何地方 |
| 2 | 每 token 解码延迟 vs 上下文（分桶中位），**不含 TTFT、不含预填充工作** | 区间伪影；口径混入 |
| 3 | 盈亏平衡生成长度 =（预填充差）/（每 token 解码收益） | 分离后丢失交易本身 |
| 4 | 延迟工作记在哪一侧的文字声明 | 时间分界线 ≠ 语义分界线 |
| 5 | **与机器无关的量**：解码每 token 每层字节数、预填充 FLOPs | 读者无法移植 |

1b 是这套口径的关键：把构建窗口从解码裁掉**只有在 1b 把它记上去之后才诚实**。
实测差别——不记的话盈亏平衡是 4.6k token，记上去是 7.8k。

### 11.1 每 token 每层字节数（与机器无关）

| S | DSA | VK r64 fp16 | VK r64 fp8 | VK/DSA |
|---|---|---|---|---|
| 4096 | 2.49 M | 3.58 M | 3.32 M | 1.33× |
| 32768 | 3.44 M | 8.40 M | 6.30 M | 1.83× |
| 65536 | 4.52 M | 13.90 M | 9.71 M | 2.15× |
| 262144 | 11.01 M | 46.93 M | 30.16 M | 2.74× |

**VestigeKV 在任何上下文都读得比 DSA 多，且比值随 S 上升。** 关键的交叉不在草图上而在注意力读上：
DSA attend 固定 2048 行，VestigeKV attend ρ·S 加召回，两者在 **S = 65536** 相遇，
此后**无论草图压多小**，VestigeKV 读的 KV 都比 DSA 多。能动这一项的只有 ρ。

**读者不要用带宽比例去缩放我们的毫秒数。** 本机在所报上下文下解码**不是**带宽瓶颈——
32k 时注意力加选择约占整步 11.3 ms 的 2.6%，整步由 MoE 权重主导。
证据是三个否定结果：4:1 池化、秩 64→16、fp16→fp8 各自都砍了字节而 ITL 纹丝不动，
而去掉一条派发链动了 1.9%。所以上表是**渐近下界**，不是我们实测时间的解释。

## 10. 工程税清零（2026-09-24）

同一 harness、同一请求序列（32k 提示 + 4096 解码），无 VestigeKV 遥测：

| | 平均 ITL | 中位 ITL | TTFT | needle |
|---|---|---|---|---|
| DSA | 11.32 ms | 11.31 | 7199 ms | OK |
| VestigeKV（`DSA_LAYERS=none`） | **11.28** | **11.25** | 7424 | OK |

**解码 −0.4%，预填充 +3.1%。**

### 10.1 解码：差距是"两条选择链"，不是字节

逐层静态角色（`SGLANG_VESTIGEKV_DSA_LAYERS`）。集合内的层跑 DSA indexer、围栏常开、不建 tier；
集合外的层永久跳过 indexer 的打分与 top-k。判定只依赖 layer id，捕获时烘进图——零重捕获、零派发成本。
成本模型是反的：DSA 链 166 µs/步 比证书链 106 µs 贵，**集合应尽可能小**，它存在的唯一理由是给会围栏的层一个可 attend 的选择。

**只有逐层同构的配置可报**（2026-09-24 定：禁止混合模式）。按每层各挑最快的机制再报总和，就是 cherry-pick；
而且那组层并不稳定，两次同配置运行给出 {23,39,27,3,19} 与 {3,7,11,15}，说明它是被拟合到某次运行上的，不是模型的性质。
所以下表里 6 层那一行**不可报**，只作为定位成本的探针留存。

| 配置 | 逐层同构 | ITL | 对 DSA |
|---|---|---|---|
| 两条链都跑（不设） | 是 | 11.53 | +1.9% |
| ~~6 层 DSA~~（探针，不可报） | 否 | 11.35 | +0.4% |
| **0 层 DSA（`none`）** | 是 | **11.27** | **−0.4%** |
| `none` + 预填充标定 | 是 | 11.18 | −1.1%（但 TTFT +17%） |

两个可报变体的差别在围栏步 attend 什么：不设 → DSA 的 top-2048；`none` → 自己的整张页表。
32k 下稠密那条很便宜（一层一步 KV 读约 13 µs，整步 11.3 ms，注意力仅占约 1%），
这也解释了为什么池化、降秩、fp8 三条压字节的路都动不了 ITL：差距从来不是流量。

**但不要把"稠密=精确=更好"当成结论。** 本模型是带 DSA 训练的，稀疏模式是它适配的分布。
`results/glm53/ruler/results_dense_mla_n10_4096-8192.json` 与 DSA 基线共有的 8 格：均值 **0.7883 对 0.8323**，
`ruler_fwe` 在 8k 上是 **0.83 → 0.23**。该臂是所有层所有步全稠密、且配置层关掉了 DSA，
幅度不能直接搬到"只在围栏步稠密"，但方向足以让 `none` 的质量成为待测项而不是假定项。

同理，速度上 `none` 也有一个随上下文恶化的项：养 indexer 是 ~15.1 µs/层/步、与 S 基本无关，
稠密 fallback 是 f×(S/32768)×13.5 µs、与 S 成正比，交叉点在 f×S ≈ 36.6k
（几乎每步围栏的层约 37k，整步均值 f=0.24 时约 152k）。**32k 恰在交叉点下方**，所以那里 `none` 赢 0.08 ms；
更长上下文上不设可能反超。交叉点是算出来的，待实测。

### 10.2 预填充：主机喂不饱设备

窗口化 trace（按设备空闲 >50 ms 切请求）显示：32k 请求上 VestigeKV 的**设备工作更少**（8823 对 9050 ms 内核时间），
**墙钟更长**（8101 对 7538 ms），且预填充注意力内核两臂同速（335 µs/次）。所以税是 GPU 空转，
来自每层每块都跑一次的预填充钩子（该提示下 671 次）。两处阻塞：

- `buf[slot] = n` 把 python 标量暂存成 H2D 拷贝并**等待流排空**：在繁忙设备上实测每次阻塞主机 3.8 ms，
  而 `buf[slot:slot+1].fill_(n)` 只要 0.7 ms。
- 保留集每块都重排一次。但两次 close 之间 sigma 只追加、`closed` 索引它的前缀，**同样的行赢得同样的 top-m**，
  变的只有未闭合的尾巴，直接追加是精确的。排序从每块一次变成每次 close 一次（64 → 8）。

钩子主机时间 332 → 180 → 94 ms；TTFT 7292 → 7104 → 7037（对 DSA 6804）。

**一个失败的中间步骤值得记下**：先尝试把重建整体推迟到首个解码步，主机时间照样降（kept 103→2、write 169→0），
**TTFT 一毫秒没动**——因为阻塞的标量写只是挪到了钩子的下一段（bookkeeping 16→216 ms）。已回退。
先拆掉阻塞，去掉工作才开始值钱。

### 10.3 测量协议的两次翻车

- `SGLANG_DEBUG_VESTIGEKV_STATS=1` 让 `_account_step` 每层每步发 ~7 个设备算子（11 层 = 77 次启动/步），
  这笔开销**只落在 VestigeKV 臂**。带它测出的差距是 +14.7%，实际是 +1.9%。**计时臂一律不带 VestigeKV 遥测。**
- 不预热时首个请求付 Triton JIT，VestigeKV 要编译的内核更多；第二个 VestigeKV 臂又命中磁盘缓存。
  由此得出过 `vk2048=5507ms` 比所有臂都快的荒谬读数。**每个新服务器先跑一个预热请求再计时。**

## 9. 召回审计与证书成本的定位（2026-09-23，修复后）

审计（eager 路径、标定证书正常，`SGLANG_DEBUG_VESTIGEKV_RECALL_AUDIT`）：11 层平均达成召回 0.896（目标 0.90），
层间 0.73–1.00；召回 1.00 的层（19、23、27、39）是靠**点火整个档案**得到的（每步 16k–31k 行），
召回 0.73–0.88 的层每步点火 3k–7k 行。DSA top-2048 对同一 oracle 的覆盖为 0.440。

**围栏成本的来源**：不是"哪层不可标定"，是阈值证书在部分层上极松。层 23 标定统计：查询真正需要的档案行 p90=2.5、最大 91，
但 0.9 保形水平要求 zp 钳到 8，证书中位点火 11k 行（单头）/ 31k 行（32 头并集）→ 每步溢出 → 每步围栏。
in-graph 的 `ovf_by_layer` 印证：层 23 在 99% 的步溢出，多数层 <2%。**DSA indexer 之所以几乎每步都跑，是一两层把整个档案点火。**

在真实标定 dump（32k，每层 8 查询×32 头）上离线量了三条路，都封死或受限：

| 路线 | 实测 | 结论 |
|---|---|---|
| 秩证书（top-K，K=目标行秩的保形分位数） | 单头 K=142–1763（点火层），但服务按 32 头**并集**点火：并集 1.3k–30k，头最大分数下 K=5k–31k | 并集下不可行 |
| 更多标定查询（8→16）、更高秩（64→256） | qres/‖q‖ 0.64→0.34；层 19 点火 265→23；**层 23 在 r=256、甚至含测试查询的 oracle 基下仍点火 31k**（qres 仍 0.45–0.57） | 层 23 结构性超出草图 |
| 留出检验（训练 10k 处查询、测试 32k 处） | 服务配置下留出召回 0.18（层 3）、0.51（层 19）、0.30（层 43） | 证书保证是标定窗内的；跨窗漂移大 |

点火分布是**全有或全无**的：中位步取回 0、均值数千。因此固定预算规则替代不了阈值；剩下能动的是**按请求的静态逐层切分**：
标定时若某层证书的并集点火在标定查询上超预算，该层本请求固定走 DSA（已有的"每请求一次合并重捕获"就是烘进图的时机）；
其余层保留证书与围栏。**每步逐层溢出向量实测**（`SGLANG_DEBUG_VESTIGEKV_OVF_TRACE`，32k，4199 步）：任一层溢出的步占 **99.7%**——精简图今天没有可精简的步。
逐层溢出率：层 23 0.993、39 0.985、27 0.896、3 0.659、19 0.333，其余 0.018（全是标定前的临时证书步）。
静态切分的最优点是 5 层固定走 DSA {23,39,27,3,19}：精简步 98.2%。成本模型（DSA 链 166 µs 均摊 11 层，VestigeKV 链 137 µs 均摊 11 层）：

| 方案 | 每步 µs | 对 DSA |
|---|---|---|
| 今天（indexer 每步全跑） | 303 | 1.82× |
| 静态 5 层 DSA，其余层 VestigeKV，只省 indexer | 214 | 1.29× |
| 同上，且 DSA 层跳过 VestigeKV 的前言/扫描/归并 | **~150** | **0.90×** |

后者在 32k 上是名义交叉，但幅度 16 µs/步（步长 11.5 ms 的 0.14%），在测量噪声内。斜率上：VestigeKV 的 0.233 ms/10 万 = indexer 增长 0.096（每步都跑）+ 前言增长 0.135；
切分后 ≈ 5/11×0.096 + 6/11×0.135 = 0.118，对 DSA 的 0.096–0.113 是**持平，不是交叉**。

工程实现上，切分掩码是按请求的：ig 的另两次运行溢出层集合不同（{3,7,11,15} 与 {3,23,39,27}），所以不能烘死在初始化捕获的图里。
两条落地路径：(a) 设备侧掩码——精简图里 indexer 的 logits/top-k 以 `seq_len × mask[layer]` 为长度运行（长度 0 即近零工作），
不需重捕获，但 hadamard/act_quant（36 µs/步，不随长度变）与空启动仍在，只拿回约 1/3 的差距（≈206 µs）；
(b) 每请求重捕获模型解码图并把掩码烘进去，拿到上表的 ~150 µs，代价是每请求一次数百毫秒的捕获和 bs>1 时的复杂度。
